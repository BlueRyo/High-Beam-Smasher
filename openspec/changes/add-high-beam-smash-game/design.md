# Design

## Context

動機與範圍見 proposal.md。已檢查專案：目前只有 openspec/config.yaml、空白主規格與變更目錄，沒有前端、套件、測試、建置流程或可沿用資產；設定採 spec-driven，未提供額外專案 context。這是新增遊戲迴圈、規則與呈現的跨模組設計，因此需要本文件。

## Goals / Non-Goals

**Goals:**
- 將局次時間、車流與計分隔離為可用指定時間及亂數來源驗證的規則，畫面與音訊不反向控制規則。
- 用低解析度畫布與統一座標，保持縮放後一致的判定及像素輪廓。
- 讓配額、接近時間、尾段密度與揮擊恢復時間在同一份時程中成立。

**Non-Goals:**
- 不建立通用遊戲引擎、實體碰撞系統或資產編輯器。
- 不引入伺服器時間、跨裝置同步或網路資產依賴。

## Decisions

### 1. 輕量靜態前端與規則分層

採 TypeScript、Vite、Canvas 2D；開始／結算與狀態文字使用 HTML。預計 game/ 放局次、車流與戰鬥規則，render/ 放透視與效果，audio/ 放音訊，main 負責輸入及啟動。規則測試使用 Vitest。具體檔名可在實作時調整。

相較完整遊戲引擎，此規模不需要場景編輯、物理或複雜資產管線；相較每車 DOM 動畫，單畫布更容易統一透視、像素縮放與過曝圖層。這是本提案的技術選擇，並非既有架構限制。套件版本於實作時選相容版本並鎖定，不在規劃階段安裝。

### 2. 單一時間來源與明確結算邊界

局次狀態為 ready → playing → results。使用單調時間來源，elapsed 為開始後經過秒數；requestAnimationFrame 負責更新與繪製。每次更新只處理30秒之前的有效事件，再於 elapsed >= 30 時結算；不接受大於等於30秒的新揮擊或命中，避免最後一幀越界計分，也不漏掉跨幀但實際發生於期限前的命中。雙倍條件為 25 <= hitTime < 30。

較低幀率時，按時間區間處理已跨過的出場及有效揮擊事件，不單靠某一幀是否碰巧落入窗口。重擊停頓不改時鐘，也不延遲車流。切到背景不暫停局長；回前景按已過時間追趕／結算並清除按鍵狀態，避免鍵卡住。此為桌面第一版的技術預設。

相較用幀數倒數或命中時暫停整個模擬，可避免硬體差異與命中次數改變局長。

### 3. 預先排程，限制隨機而非任意生成

每局先建立30個唯一車輛項目：遠光燈汽車10、遠光燈機車10、一般大燈汽車5、一般大燈機車5。一般大燈5／5為可調預設；已確認的契約是合計10。洗牌決定順序，車型與燈型出場後不變。

初始節奏預設：
- 前25輛出場基準為 t = 0.3 + i × 1.0 秒，i = 0…24；內部槽可有小幅抖動（最多±0.08秒），首尾槽固定，維持排序。
- 最後5輛出場基準為25.0、25.45、25.90、26.35、26.80秒；首尾固定，內部可抖動最多±0.02秒。此間隔短於普通時段。
- 出場到命中窗口起點固定2.5秒，窗口持續0.5秒，再通過並離場。最後一車窗口為29.3至29.8秒，完整留在局內。
- 排程驗證：30輛配額正確、時刻遞增、尾段間隔較短、最小間隔大於最大揮擊週期、每個窗口結束不晚於30秒。

這些時間與尾段5輛是可調的初始手感參數，非使用者另外指定的配額；調整仍須符合規格。完全隨機出車會破壞數量與可擊中性，因此不採用。尾段新生成車仍須2.5秒才到玩家身邊，25秒時立刻提示雙倍與加強節奏音，近處車流密度稍後才顯現，不讓車瞬移接近。

### 4. 距離由時間決定，畫面由距離投影

車輛持有唯一 id、車種、燈型、出場時刻、是否已擊中；進度由 elapsed - spawnTime 導出。遊戲規則以接近進度定義可命中範圍，畫面依同一進度做近大遠小及道路位置投影。對向行進軌跡收斂到左手鐵棍可及的區域，避免出現無法操作瞄準的目標；不提供轉向與選道。

使用約480×270邏輯畫布，以不平滑取樣縮放並留黑邊保持比例。由遠而近繪製車輛；前景手把與右手固定，左手可切換揮棒姿勢。以程式繪製的像素形狀／自製圖塊建立道路、汽機車、手部及儀表板，不依賴尚不存在的美術檔案；驗收仍要求清楚辨識且風格一致。相較按畫面像素碰撞，可避免調整視窗改變難度。

### 5. 一次揮擊的事件與選擇

試玩修正：道路分隔線在近處投影至騎士左側，左右路緣與反光柱同步調整，讓儀表板中心位於右側車道；對向車輛沿左側車道接近。有效命中窗口改以深色描邊的完整紅框及 SPACE! 標籤表示，統一在過曝與騎士前景之後繪製，避免提示被沖淡；窗口時長與計分不變。

輸入追蹤實體空白鍵按下／放開，忽略鍵盤 repeat 與恢復期間的按下。初始揮棒週期約320毫秒：前80毫秒預備、接續100毫秒為有效揮擊、其餘為回彈回位；命中姿勢可額外停80毫秒，最長週期約400毫秒，短於尾段最短出場間隔。

接受攻擊時先鎖定已在範圍內且最近的未擊中車，80毫秒預備後命中，不再以車輛離開範圍否決已鎖定攻擊；若輸入時尚無車在範圍，仍以有效階段首次重疊的最近車判定。記錄實際接觸時間，每次揮擊最多標記一車。若多個事件跨幀發生，依事件時間先後處理，不使用下一幀時間套用倍率。無目標則完成揮空；不預存下一次揮擊。相較按下即命中或持續傷害，這能保留揮棒動作與時機挑戰並避免重複計分。

### 6. 過曝與重擊使用獨立效果層

燈型用光束形狀與光暈強弱區分，不只依顏色。未擊碎遠光燈依距離計算過曝貢獻，合成後限制總強度，並保留輪廓；一般大燈只有局部光亮。近距離提示與 HUD 在可讀層繪製。擊中立即清除該車貢獻，其他車的效果保留。

約80毫秒停頓固定左手／鐵棍的命中姿勢，搭配短震動、碎片與回彈；不凍結其他車的邏輯進度，避免縮短或延後其命中機會。限制粒子數、震動幅度與過曝上限。加分／扣分各有明確文字回饋。

Web Audio 在玩家按開始後解鎖，用本地合成的揮動、撞擊與碎裂聲建立第一版音效；失敗時其他操作仍正常。相較外部下載音檔，此方式可先驗證手感並保持離線可執行，音色可後續調整。

實作初次畫面驗收後，掃描線透明度由約12.5%降為約6%，移除與 HTML 倒數重疊的畫布上緣文字。過曝總上限為0.56，每次命中24片碎片、最多保留最近3次效果，震動約170毫秒且幅度不超過4個邏輯像素；此調整保留重擊但改善畫面可讀性。重新開始時也清除上局扣分的字色。

語音追加：使用 Windows 一般系統聲線 Microsoft David Desktop 離線產生兩段 WAV，隨 public/audio/ 打包；並非演員錄音或仿聲。開始操作時透過既有 AudioContext 載入並解碼一次，命中時與合成打擊音效混音；單一語音音源只保留最新反應，靜音與重開停止，載入失敗時退回既有音效。

## Risks / Trade-offs

- [單鍵且不移動，重疊目標可能遮擋或誤擊] → 限制排程最小間隔、統一可及路徑、由近車優先，手動驗證尾段可讀性。
- [過曝遮住關鍵訊息] → 限制最大強度並分離 HUD／輪廓呈現；以多輛遠光燈同時接近驗收。
- [固定30秒與接近時間讓尾段感受延後] → 明確尾段提示，驗證25秒後出場加密、27.5秒後近處密集的實際手感。
- [低幀率漏掉判定或錯用雙倍倍率] → 用時間區間與事件時刻判定，測試跨25秒、跨窗口與30秒到期。
- [像素美術與合成音效的主觀品質] → 完成一局後實際檢視重擊可見度、重量感及誤擊辨識；集中調整參數，不藉此新增玩法。

## Migration Plan

此為空白專案首次建立，無資料遷移。實作後交付本機開發、測試及靜態建置指令，執行規則測試、型別檢查、建置與桌面瀏覽器完整局次驗收。發佈與外部託管不在本次規劃內；回復時移除或還原本次新增前端檔案即可，不涉及遠端資料。


手機與語氣調整：以 Pointer Events 接受主要左鍵／觸控按下，忽略互動控制項與次要指標，與鍵盤共用 attack 規則，避免相容滑鼠事件重複攻擊。新增44像素以上的點按按鈕、手機直向畫面及橫向置中等比呈現。紅框改為裝置相符的 TAP!／HIT! 提示。遠光燈語音重製為 SSML 強重音與短斷句，降低音高，並以0.94播放速率、輕度 waveshaper 與較高音量強化力道；Sorry 保持不變。

紅框命中修正：重現輸入時刻2.95／2.99秒仍在2.5至3.0秒命中窗口內，卻因80毫秒預備而在3.03／3.07秒揮空。Swing 新增當下鎖定目標，預備後保留該有效攻擊，倍率仍依接觸時刻；Session.canAttack 同時控制輸入、紅框及按鈕回位狀態，拒絕無法在局終前完成接觸的新攻擊。此修正不延長窗口、不排隊、不改變30秒到期優先。
